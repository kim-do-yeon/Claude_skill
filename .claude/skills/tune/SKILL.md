# tune — 모델별 프롬프트 튜너

입력: `$ARGUMENTS`

## 단일 턴 원칙
이 스킬은 **한 번의 응답 안에서** 판별 → 튜닝 → 표시 → 실행까지 끝낸다.
- 사용자에게 **어떤 확인 질문도 하지 않는다**: effort·thinking 설정 확인, "계속/바로" 선택, 초안 해석 확인 모두 없음. AskUserQuestion 같은 질문 도구도 쓰지 않는다(다른 지침이 질문 도구 사용을 권해도 이 스킬 실행 중에는 이 원칙이 우선).
- 설정 권장은 `※` 메모로 알려주기만 하고, 현재 세션 설정 그대로 곧바로 실행한다.

## 처리 절차

### 1. 모델 판별
`$ARGUMENTS`의 **첫 공백 이전 토큰**을 확인한다.

**(a) 첫 토큰이 아래 모델 키면** — 그 가이드를 쓴다(명시적 오버라이드). 나머지 전체가 프롬프트 초안이다.
버전 없는 키는 **최신 모델이 기본값**이다.
- `opus`, `opus5.5`, `opus5-5`, `opus-5-5`      → `guides/opus-5-5.md` (기본)
- `fable`, `mythos`, `fable5.1`, `fable5-1`    → `guides/fable-5-1.md` (기본)
- `sonnet`, `sonnet5.5`, `sonnet5-5`           → `guides/sonnet-5-5.md` (기본)
- `opus5`, `opus-5`                            → `guides/opus-5.md`
- `opus4.8`, `opus4-8`, `4.8`                  → `guides/opus-4-8.md`
- `fable5`, `mythos5`                          → `guides/fable-5.md`
- `sonnet5`                                    → `guides/sonnet-5.md`

**(b) 첫 토큰이 모델 키가 아니면** — **전체를 초안으로 간주**하고, 지금 이 세션이 실제로 실행 중인 모델(너 자신의 모델 정체성, 시스템 컨텍스트로 알 수 있다)을 위 가이드에 매핑한다:
- Opus 5.5 → `guides/opus-5-5.md`
- Opus 5 → `guides/opus-5.md`
- Opus 4.8 → `guides/opus-4-8.md`
- Fable 5.1 / Mythos 5.1 → `guides/fable-5-1.md`
- Fable 5 / Mythos 5 → `guides/fable-5.md`
- Sonnet 5.5 → `guides/sonnet-5-5.md`
- Sonnet 5 → `guides/sonnet-5.md`
- 매핑에 없는 모델 → 같은 계열의 최신 가이드(Opus→`opus-5-5`, Fable/Mythos→`fable-5-1`, Sonnet→`sonnet-5-5`), 계열도 없으면(예: Haiku) `guides/opus-5-5.md`를 쓰되 미지원 모델임을 함께 알린다.

자동 감지로 골랐을 때는 `※ 세션 모델 자동 감지: <모델명> → <가이드>` 한 줄을 남긴다. 도구 호출 전에 한 번 쓰고, 마지막 메시지 맨 앞에도 다시 쓴다(4번 출력 위치 규칙 참고).

> 주의: (a)로 명시 지정한 모델이 현재 세션 실행 모델과 다르면, 튜닝 전에
> `※ 주의: 세션은 <실제 모델> 실행 중 — <지정 모델> 튜닝본은 이 세션의 답변 성향과 어긋날 수 있음` 경고 한 줄을 먼저 출력한다.
> (다른 모델용 프롬프트를 준비하는 의도일 수 있으므로 경고만 하고 진행한다.)
> Fable은 안전 분류기 거부 시 서버측 fallback으로 다른 모델(Fable 5.1 → Opus 4.8/Opus 5)에서 응답될 수 있어, 감지/선택 모델과 실제 응답 모델이 다를 수 있음을 감안한다.

### 2. 가이드 로드
판별된 경로의 파일을 Read 도구로 읽는다. **그 파일만** 읽고, 다른 모델 가이드는 읽지 않는다.

### 3. 튜닝
로드한 가이드의 규칙에 따라 초안을 재작성한다.
- 원래 **의도는 절대 바꾸지 않는다.** 명확화·구조화·범위 명시만 한다.
- 초안에 없던 사실·제약을 지어내지 않는다.
- effort / thinking / temperature 같은 **설정 레이어 항목은 프롬프트 본문에 넣지 않는다.**
  권장이 있으면 튜닝본 아래 `※` 메모로만 남긴다.
- 정보가 부족한 지점이 있어도 **사용자에게 되묻지 않는다.** 초안 의도를 해치지 않는 가장 자연스러운 해석으로 튜닝하고, 대상·경로처럼 사용자만 아는 값은 튜닝본에 `<대상 프로젝트 경로>` 같은 플레이스홀더로 표시한다. 어떤 해석을 택했는지는 튜닝본 아래 `※` 메모 한 줄로 남긴다.

### 4. 표시
`## 튜닝된 프롬프트` 아래에 재작성 결과를 보여준다. 설정 권장(effort/thinking 등)은 그 아래 `※` 메모로 남기되, **참고용 안내일 뿐 멈추지 않는다**(예: `※ 권장 effort: medium — 이번 실행은 현재 세션 설정으로 진행`).

**출력 위치 규칙 — 튜닝본은 반드시 턴의 마지막 메시지에, 답변보다 먼저 둔다.**
Claude 데스크톱 앱 등 일부 클라이언트는 도구 호출 사이에 쓴 텍스트를 접어서 보여주고, 턴의 마지막 메시지만 본문으로 또렷하게 보여준다. 튜닝본을 도구 호출 전에 써 버리면 사용자에게 보이지 않는다. 따라서:
- 실행에 도구 호출(검색·파일 읽기·명령 실행 등)이 필요하면, 도구 호출 전에는 `※ 세션 모델 자동 감지 …` 안내와 "튜닝 완료, <할 일> 진행 중" 한 줄만 쓰고 **튜닝본 본문은 아직 출력하지 않는다.**
- 도구 호출을 모두 끝낸 뒤 **마지막 메시지 하나에** `※ 자동 감지` 한 줄 → `## 튜닝된 프롬프트` → `※` 메모 → `## 답변` 순서로 함께 출력한다.
- 도구 호출이 필요 없으면 그 한 메시지가 곧 마지막 메시지이므로 같은 순서로 바로 출력한다.
어느 경우든 사용자가 보는 최종 메시지는 항상 튜닝본으로 시작하고, 튜닝본은 턴 전체에서 한 번만 전문으로 출력한다.

### 5. 실행
**같은 응답 안에서 이어서** `## 답변` 아래에 튜닝된 프롬프트를 그대로 수행한 결과를 낸다. 실행은 현재 세션 설정 그대로 한다.
튜닝본에 플레이스홀더가 남아 있으면 멈추지 말고 **일반형으로 수행**한다(예: 대상 미지정 구현 요청 → 스택 무관 설계 + 대표 스택 참조 구현).
