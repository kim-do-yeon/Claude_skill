# tune — 모델별 프롬프트 튜너 (Claude Code 스킬)

## 개요

`/tune`은 프롬프트 초안을 **지금 답변할 모델**(Opus 5 / Opus 4.8 / Fable 5 / Sonnet 5)의 프롬프트 가이드에 맞춰 자동으로 재작성한 뒤, 그 튜닝본으로 바로 답변까지 내주는 Claude Code 스킬입니다. 모델마다 지시를 받아들이는 성향이 달라 같은 프롬프트도 결과가 갈리는 문제를, 모델별 가이드 문서 하나로 흡수합니다. 원래 의도는 바꾸지 않고 명확화·구조화·범위 명시만 합니다.

## 설치

이 저장소를 받아서 `.claude/skills/tune/` 폴더를 프로젝트(또는 개인 전역)의 같은 위치에 두면 끝입니다.

**프로젝트 단위 설치** (해당 프로젝트에서만 사용):

```bash
git clone <이-저장소-URL> claude_skill
mkdir -p <프로젝트-루트>/.claude/skills
cp -R claude_skill/.claude/skills/tune <프로젝트-루트>/.claude/skills/tune
```

**개인 전역 설치** (모든 프로젝트에서 사용):

```bash
git clone <이-저장소-URL> claude_skill
mkdir -p ~/.claude/skills
cp -R claude_skill/.claude/skills/tune ~/.claude/skills/tune
```

별도 활성화 절차는 없습니다. 파일을 둔 뒤 Claude Code 세션에서 `/tune`을 입력하면 스킬이 인식됩니다(이미 실행 중인 세션이라면 새 세션에서 확인하세요).

설치 후 구조:

```
.claude/skills/tune/
├── SKILL.md            # /tune <model> <초안> 오케스트레이션
└── guides/
    ├── opus-4-8.md     # Opus 4.8 튜닝 규칙
    ├── opus-5.md       # Opus 5 튜닝 규칙
    ├── fable-5.md      # Fable 5 튜닝 규칙
    └── sonnet-5.md     # Sonnet 5 튜닝 규칙
```

## 사용법

**기본 사용은 초안만 넘기면 됩니다** — 현재 세션이 실행 중인 모델을 자동 감지해 그 가이드로 튜닝합니다.

```
/tune 우리 서비스 랜딩페이지 히어로 섹션 만들어줘
```

자동 감지 시 응답 맨 앞에 `※ 세션 모델 자동 감지: <모델명> → <가이드>` 안내가 붙습니다.

**다른 모델용 프롬프트를 준비할 때만** 첫 인자로 모델 키를 명시합니다(오버라이드). 이때 지정 모델이 세션 모델과 다르면 경고 한 줄이 먼저 출력됩니다.

```
/tune sonnet 우리 서비스 랜딩페이지 히어로 섹션 만들어줘
```

```
/tune opus 이 레포에서 결제 로직 버그 찾아서 고쳐줘
```

```
/tune fable 지난 분기 로그 전체를 분석해서 장애 패턴 보고서를 만들어줘
```

```
/tune opus4.8 결제 모듈 전체를 리팩터링하고 회귀 테스트까지 통과시켜줘
```

인식하는 모델 키(오버라이드용):

| 모델 | 키 |
|---|---|
| Opus 5 | `opus`, `opus5`, `opus-5` |
| Opus 4.8 | `opus4.8`, `opus4-8`, `4.8` |
| Fable 5 | `fable`, `mythos`, `fable5` |
| Sonnet 5 | `sonnet`, `sonnet5` |

첫 토큰이 이 중 어디에도 해당하지 않으면 **전체를 초안으로 간주하고 세션 모델 자동 감지**로 동작합니다. 세션 모델이 위 4종에 없으면(예: Haiku) Opus 5 가이드를 적용하고 미지원 모델임을 알립니다.

**출력 형태**:

1. `## 튜닝된 프롬프트` — 해당 모델 가이드에 맞춰 재작성된 초안. effort 등 설정 권장이 있으면 그 아래 `※` 메모로 표시.
2. **설정 권장이 있으면 여기서 한 번 멈춥니다.** 권장 설정(effort 등)을 적용하고 싶으면 `/model` 등에서 조정한 뒤 **"계속"**, 현재 설정 그대로 진행하려면 **"바로"**라고 답하세요. 실행은 그 답변 시점의 세션 설정으로 이뤄지므로, 권장을 실제로 반영할 수 있는 타이밍입니다.
3. `## 답변` — 튜닝된 프롬프트를 그대로 수행한 실제 결과. (설정 권장이 없으면 멈춤 없이 바로 이어집니다.)

초안에 정보가 부족해도 되묻지 않습니다. 가장 자연스러운 해석으로 튜닝하되, 대상 경로처럼 사용자만 아는 값은 튜닝본에 `<플레이스홀더>`로 표시하고 어떤 해석을 택했는지 `※` 메모로 남깁니다.

## 동작 원리

1. **모델 판별** — `/tune` 뒤 첫 토큰이 모델 키면 그 가이드를(오버라이드), 아니면 전체를 초안으로 보고 **현재 세션 실행 모델을 자동 감지**해 매핑합니다.
2. **가이드 로드** — 판별된 모델의 가이드 파일 **하나만** 읽습니다. 다른 모델 가이드는 읽지 않으므로 컨텍스트가 섞이지 않습니다.
3. **튜닝** — 가이드 규칙에 따라 초안을 재작성합니다. 의도 변경 금지, 없던 사실·제약 추가 금지, 설정 레이어 항목(effort/thinking/temperature)은 본문에 넣지 않고 `※` 메모로만.
4. **표시 → (설정 확인) → 실행** — 튜닝본을 먼저 보여주고, 설정 권장이 있으면 사용자가 설정을 조정할 수 있게 한 번 멈춘 뒤, 그 프롬프트를 수행한 답변을 냅니다.

`SKILL.md`는 이 오케스트레이션만 담당하고, 모델별 규칙은 전부 `guides/`에 있습니다.

## 가이드 수정·확장

- **규칙 수정**: `guides/` 안의 해당 모델 파일만 고치면 다음 `/tune` 호출부터 바로 반영됩니다. `SKILL.md`는 건드릴 필요 없습니다.
- **새 모델 추가**: ① `guides/<새-모델>.md`를 기존 가이드와 같은 꼴(핵심 성향 / 튜닝 규칙 / 설정 레이어)로 작성하고, ② `SKILL.md`의 "1. 모델 판별" 매핑 목록에 `키 → guides/<새-모델>.md` 한 줄을 추가합니다.

## 한계

- **모델 키를 명시 지정하면 세션 모델과 어긋날 수 있습니다.** 기본(자동 감지) 사용에서는 문제가 없지만, 오버라이드 시 지정 모델과 세션 모델이 다르면 튜닝본과 이어지는 답변의 성향이 어긋날 수 있어 경고가 출력됩니다. 다른 모델용 프롬프트를 준비하는 경우라면 `## 답변`이 아닌 `## 튜닝된 프롬프트`만 가져다 쓰세요.
- **설정 레이어는 프롬프트로 바꿀 수 없습니다.** effort, thinking, temperature 등은 API/클라이언트 설정 영역이라, 스킬은 권장값을 `※` 메모로 알려줄 뿐 적용하지는 못합니다.
- **Fable 5는 안전 라우팅으로 Opus 4.8에 폴백될 수 있습니다.** 특정 카테고리를 겨냥한 분류기에 걸리면(선의의 작업도 걸릴 수 있음) 실제 응답 모델이 선택 모델과 달라질 수 있습니다.
